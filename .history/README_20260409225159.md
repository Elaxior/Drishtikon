# drishtikon

drishtikon is a full-stack hackathon project that helps users search a news topic and (in later parts) compare coverage from multiple sources to identify consensus and disagreement.

This repository now includes:
- Part 1 foundation (health check, frontend-backend connectivity, modular structure)
- Part 2 NewsData.io integration via backend `/search` endpoint
- Part 3 source bias detection labels for each article
- Part 4 LLM-based factual claim extraction for each article
- Part 5 embedding-based consensus engine for grouped claims
- Part 6 neutral multi-source summary generation
- Part 7 cached trending feed with focused world sections
- Part 8 modernized UI and reusable component architecture
- Part 9 dedicated analysis page for structured decision view
- Part 10 chart-driven consensus visualization

## Environment Setup

Create `backend/.env`:

```env
NEWSDATA_API_KEY=your_key_here
GROQ_API_KEY=your_key_here
```

Optional environment variables:

```env
FRONTEND_ORIGIN=http://localhost:5173
NEWSDATA_BASE_URL=https://newsdata.io/api/1
NEWSDATA_TIMEOUT_SECONDS=10
NEWSDATA_PAGE_SIZE=10
GROQ_MODEL=llama-3.1-8b-instant
SUPADATA_API_KEY=your_supadata_key_here
SUPADATA_BASE_URL=https://api.supadata.ai/v1
SUPADATA_TIMEOUT_SECONDS=20
SUPADATA_POLL_RETRIES=6
SUPADATA_TRANSCRIPT_MODE=native
CLAIMS_ARTICLE_LIMIT=5
CONSENSUS_CLAIMS_PER_ARTICLE=3
CONSENSUS_SIMILARITY_THRESHOLD=0.75
ENABLE_PINECONE=false
PINECONE_API_KEY=your_pinecone_key_here
PINECONE_INDEX_NAME=drishtikon-claims
PINECONE_NAMESPACE=claims
PINECONE_CLOUD=aws
PINECONE_REGION=us-east-1
PINECONE_EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2
PINECONE_EMBEDDING_DIMENSION=384
PINECONE_TOP_K=5
PINECONE_MATCH_THRESHOLD=0.82
PINECONE_QUERY_CLAIM_LIMIT=8
```

`NEWSDATA_PAGE_SIZE` is capped to a max of 12 to help prevent unnecessary API credit usage.
`CLAIMS_ARTICLE_LIMIT` is capped to a max of 5 to control LLM latency and cost.
`CONSENSUS_CLAIMS_PER_ARTICLE` is capped to a max of 3 to keep consensus processing fast.
`SUPADATA_API_KEY` enables richer Instagram Reel metadata/transcript extraction for social-link analysis.
`SUPADATA_TRANSCRIPT_MODE=native` is recommended for faster responses; use `auto` for deeper extraction with higher latency.
Set `ENABLE_PINECONE=true` to enable optional historical claim matching and vector upserts.
`PINECONE_EMBEDDING_DIMENSION` must match your Pinecone index dimension (for example 1024).

## Frontend-Backend Flow

- Frontend calls backend `/search` through `frontend/src/lib/api.ts`
- Backend calls NewsData.io `/latest` with:
	- `apikey`
	- `q`
	- `language=en`
	- `category=world,politics`
	- `size=10` (configurable, hard-capped to max 12)
- Backend enriches each article with source bias and LLM-extracted claims
- Backend processes only top 5 articles for claim extraction (configurable, hard-capped at 5)
- Backend groups semantically similar claims and returns a consensus score
- Backend generates a neutral summary from top articles with fallback handling
- Backend serves a cached trending feed split into General, War, and Geopolitics

### Bias Detection (Part 3)

drishtikon now adds a bias label to every article using four categories:
- `LEFT`
- `CENTER`
- `RIGHT`
- `UNKNOWN`

This is an MVP hybrid setup inspired by public media-bias references such as AllSides:
- Primary path: hardcoded source-to-bias map for fast, deterministic classification
- Fallback path: `UNKNOWN` for unmapped sources (LLM fallback will be added in a later part)

Why this design:
- Hardcoded map gives stable outputs and low latency for known outlets
- `UNKNOWN` avoids unsafe guesses when a source is missing/new
- This creates a structured signal for future consensus scoring and visualization

### Claim Extraction (Part 4)

drishtikon now extracts factual claims from each article using Groq (Llama models) in JSON mode.

Purpose:
- Convert long-form article text into atomic, verifiable claims
- Prepare data for future cross-source claim matching and consensus detection

How it works (MVP):
- Input text is `title + description`
- LLM returns JSON in shape: `{ "claims": ["...", "..."] }`
- If extraction fails, claims default to an empty list for stability

Example:

```json
{
	"title": "...",
	"source": "...",
	"claims": [
		"India announced a bilateral trade agreement on Monday.",
		"The agreement includes tariff reductions in selected sectors."
	]
}
```

Limitations (MVP):
- Claim quality depends on source text quality and model output
- No caching yet, so response time increases with LLM calls
- No claim verification step yet; verification will be added in later parts

### Consensus Engine (Part 5)

drishtikon now computes claim-level agreement using embeddings and cosine similarity.

Embedding model:
- `sentence-transformers/all-MiniLM-L6-v2`

Grouping logic:
- Convert claims into embeddings
- Compute cosine similarity between all claim pairs
- Group claims when similarity is above `0.75`

Consensus formula:
- `consensus = (largest_group_size / total_claims) * 100`

Example:

```json
{
	"claim_groups": [
		{
			"representative_claim": "India signed a trade deal",
			"sources": ["BBC", "CNN"],
			"count": 2
		}
	],
	"consensus": 66.67
}
```

MVP constraints for speed:
- Process max 3-5 articles (configured via `CLAIMS_ARTICLE_LIMIT`, hard-capped at 5)
- Use max 3 claims per article for consensus grouping
- Empty/missing claims return safe defaults (`claim_groups: []`, `consensus: 0`)

### Neutral Summary (Part 6)

drishtikon now generates a neutral, concise summary across multiple sources using Groq.

Purpose:
- Provide one clear factual view so users do not need to read many full articles
- Reduce source-specific framing by synthesizing overlap across outlets

Prompt design:
- Role: neutral geopolitical analyst
- Rules enforce factual language, no emotional framing, no speculation, and no political favoritism
- Input is a structured multi-source block including source, bias, title, and description

Example summary:

```text
Officials from multiple countries confirmed a new trade agreement framework after bilateral talks. Statements from government representatives indicate tariff adjustments are planned in phased stages. Reports agree that implementation timelines are under review by policy teams. Coverage across sources indicates negotiations focused on market access and regulatory coordination. No final enforcement date has been officially announced.
```

Limitations (MVP):
- Quality depends on available article descriptions and model output
- No citation-level traceability yet from summary sentence to specific claim
- Summary falls back to `Summary unavailable` if LLM access fails

### Trending System (Part 7)

The app now includes a dedicated `/trending` feed so users can see important stories without typing a query.

Sections:
- `general`: top category headlines
- `war`: focused query on active conflict regions (`ukraine`, `russia`, `gaza`, `israel`, `sudan`, `myanmar`)
- `geopolitics`: strategic-power query with India focus (`us china`, `china taiwan`, `india`, `modi`, `brics`, `quad`)

Query and credit strategy:
- Each section fetches only 5 articles
- Total request volume stays around 15 articles per refresh
- Every item includes `title`, `description`, `source`, `bias`, and a short `keyword`

Caching strategy:
- In-memory backend cache
- Cache TTL is 10 minutes
- Repeated `/trending` calls within TTL return cached data (no new upstream API calls)

Frontend integration:
- New route: `/trending`
- Cards include source + bias and a `View Analysis` button
- Clicking a card navigates to `/` with `?q=<keyword>` and auto-runs analysis

### Analysis Page (Part 9)

Part 9 introduces a dedicated `/analysis` page, which is now the core decision screen of drishtikon.

Page structure:
- AI Neutral Summary
- Consensus Score (with progress bar)
- Claim Comparison (grouped claims + source bias context)
- Sources List (click-through links, source name, bias badge)

Components:
- `SummaryCard` (reused)
- `ConsensusCard`
- `ClaimGroup`

Data flow:
- Route: `/analysis?q=<topic>`
- On load, the page reads query param `q`
- Calls backend `/search?q=...`
- Renders structured results in priority order: summary, consensus, claims, sources

Why this is the core feature:
- Separates search input from analysis output for a cleaner user journey
- Presents all high-value signals in one screen for quick understanding
- Makes judging easier by showing neutrality, agreement, and evidence sources immediately

Navigation updates:
- Home search now routes to `/analysis?q=<topic>`
- Trending card actions route directly to `/analysis?q=<keyword>`

### Visualization (Part 10)

Part 10 upgrades consensus rendering from a linear progress indicator to a chart-based visual.

Chart stack:
- `chart.js`
- `react-chartjs-2`

Consensus display:
- Doughnut chart with 2 segments:
	- Agreement = `consensus`
	- Disagreement = `100 - consensus`
- Center label showing `X% Consensus`
- Color mapping:
	- Green = Agreement
	- Red = Disagreement

Why this matters:
- Users interpret agreement vs disagreement instantly
- Visual ratio is faster to understand than raw numbers alone
- Strong visual clarity helps demos and hackathon judging
