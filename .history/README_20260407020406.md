# drishtikon

drishtikon is a full-stack hackathon project that helps users search a news topic and (in later parts) compare coverage from multiple sources to identify consensus and disagreement.

This repository now includes:
- Part 1 foundation (health check, frontend-backend connectivity, modular structure)
- Part 2 NewsData.io integration via backend `/search` endpoint
- Part 3 source bias detection labels for each article
- Part 4 LLM-based factual claim extraction for each article
- Part 5 embedding-based consensus engine for grouped claims

## Environment Setup

Create `backend/.env`:

```env
NEWSDATA_API_KEY=your_key_here
GROQ_API_KEY=your_key_here
```

Optional environment variables:

```env
FRONTEND_ORIGIN=http://localhost:5173
NEWSDATA_BASE_URL=https://newsdata.io/api/1
NEWSDATA_TIMEOUT_SECONDS=10
NEWSDATA_PAGE_SIZE=10
GROQ_MODEL=llama-3.1-8b-instant
CLAIMS_ARTICLE_LIMIT=5
CONSENSUS_CLAIMS_PER_ARTICLE=3
CONSENSUS_SIMILARITY_THRESHOLD=0.75
```

`NEWSDATA_PAGE_SIZE` is capped to a max of 12 to help prevent unnecessary API credit usage.
`CLAIMS_ARTICLE_LIMIT` is capped to a max of 5 to control LLM latency and cost.
`CONSENSUS_CLAIMS_PER_ARTICLE` is capped to a max of 3 to keep consensus processing fast.

## Frontend-Backend Flow

- Frontend calls backend `/search` through `frontend/src/lib/api.ts`
- Backend calls NewsData.io `/latest` with:
	- `apikey`
	- `q`
	- `language=en`
	- `category=world,politics`
	- `size=10` (configurable, hard-capped to max 12)
- Backend enriches each article with source bias and LLM-extracted claims
- Backend processes only top 5 articles for claim extraction (configurable, hard-capped at 5)
- Backend groups semantically similar claims and returns a consensus score

### Bias Detection (Part 3)

drishtikon now adds a bias label to every article using four categories:
- `LEFT`
- `CENTER`
- `RIGHT`
- `UNKNOWN`

This is an MVP hybrid setup inspired by public media-bias references such as AllSides:
- Primary path: hardcoded source-to-bias map for fast, deterministic classification
- Fallback path: `UNKNOWN` for unmapped sources (LLM fallback will be added in a later part)

Why this design:
- Hardcoded map gives stable outputs and low latency for known outlets
- `UNKNOWN` avoids unsafe guesses when a source is missing/new
- This creates a structured signal for future consensus scoring and visualization

### Claim Extraction (Part 4)

drishtikon now extracts factual claims from each article using Groq (Llama models) in JSON mode.

Purpose:
- Convert long-form article text into atomic, verifiable claims
- Prepare data for future cross-source claim matching and consensus detection

How it works (MVP):
- Input text is `title + description`
- LLM returns JSON in shape: `{ "claims": ["...", "..."] }`
- If extraction fails, claims default to an empty list for stability

Example:

```json
{
	"title": "...",
	"source": "...",
	"claims": [
		"India announced a bilateral trade agreement on Monday.",
		"The agreement includes tariff reductions in selected sectors."
	]
}
```

Limitations (MVP):
- Claim quality depends on source text quality and model output
- No caching yet, so response time increases with LLM calls
- No claim verification step yet; verification will be added in later parts

### Consensus Engine (Part 5)

drishtikon now computes claim-level agreement using embeddings and cosine similarity.

Embedding model:
- `sentence-transformers/all-MiniLM-L6-v2`

Grouping logic:
- Convert claims into embeddings
- Compute cosine similarity between all claim pairs
- Group claims when similarity is above `0.75`

Consensus formula:
- `consensus = (largest_group_size / total_claims) * 100`

Example:

```json
{
	"claim_groups": [
		{
			"representative_claim": "India signed a trade deal",
			"sources": ["BBC", "CNN"],
			"count": 2
		}
	],
	"consensus": 66.67
}
```

MVP constraints for speed:
- Process max 3-5 articles (configured via `CLAIMS_ARTICLE_LIMIT`, hard-capped at 5)
- Use max 3 claims per article for consensus grouping
- Empty/missing claims return safe defaults (`claim_groups: []`, `consensus: 0`)
